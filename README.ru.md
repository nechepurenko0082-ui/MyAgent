# MyAgent

Персональный ИИ-агент в Telegram: с терминалом, долговременной памятью, голосовыми
ответами и собственным «серверным телом». Один агент, один контекст, много
переключателей.

English: [README.md](README.md)

Собрано на Python 3.14 + Aiogram 3 + OpenAI-совместимый API (AITunnel),
работает как systemd user service.

## Что умеет

- **Telegram-бот** — ответы владельцу доставляются автоматически, финальным
  текстом; `telegram_send` — для адресных сообщений другим. Обычные пользователи
  получают контракт «один вопрос — один ответ».
- **Агентский цикл** — reasoning-модель с tool calling, повторы при 5xx и
  таймаутах, гибридная история (SQLite + кэш в памяти).
- **Доступ к серверу** — `run_command` (bash), файловые инструменты
  (`read_file`, `edit_file`, `write_file`, `search_code`) под тумблером.
- **Долговременная память** — `memory_save` / `memory_load` / `memory_forget` на
  отдельной SQLite. Доступна всегда, даже при выключенном терминале.
- **Голос** — TTS-ответы через `send_voice` (wav → ogg/opus, статичный ffmpeg
  в комплекте), тумблер «Голос».
- **Напоминания и расписание** — фоновый цикл отрабатывает напоминания каждые 30 с
  (`reminder_add`, `reminder_list`, `reminder_delete`), время московское.
- **Интернет** — `web_search` и `web_fetch` под тумблером «Поиск».
- **Удалённый ПК** — управление своим компьютером с сервера: очередь команд,
  вывод, уведомления о выключении/перезагрузке. TLS с пиннингом сертификата.
  Подробности: [remote/README.ru.md](remote/README.ru.md)

## Тумблеры

| Кнопка       | Эффект при выключении                        |
|--------------|----------------------------------------------|
| Мышление     | Reasoning отключён (быстрее и дешевле)       |
| Терминал     | Нет bash и файловых инструментов             |
| Пользователи | Сообщения пользователей не доходят до агента |
| Поиск        | `web_search` / `web_fetch` недоступны        |
| Голос        | Текст вместо голосовых                       |
| `/price on`  | Маршрутизация на дешёвый провайдер (`off` = минимальная задержка) |

## Регистрация пользователей

1. Посторонний шлёт `/start` → создаётся заявка `pending`.
2. Агент смотрит заявку и спрашивает владельца: да или нет.
3. После одобрения первое сообщение пользователя сохраняется как его имя —
   по нему же к нему и обращаются в `telegram_send`.

## Отправка по имени

`telegram_send` находит получателя по имени, ID хардкодить не нужно:

```json
{"text": "привет", "name": "Lera"}   // → ищется в таблице пользователей
{"text": "привет"}                   // → тому, кто писал последним
```

Неизвестное или неоднозначное имя → вежливая ошибка, без падений.

## Установка

```bash
# 1. Переменные окружения
cat > .env <<'EOF'
BOT_TOKEN=...
AITUNNEL_API_KEY=...
ALLOWED_USER_ID=...
MODEL_NAME=qwen3.8-flash
USER_ALIASES=имя:id,имя:id
EOF

# 2. Зависимости
python3 -m venv venv && venv/bin/pip install -r requirements.txt

# 3. Запуск
venv/bin/python agent.py
```

Как systemd user service:

```bash
systemctl --user start myagent
journalctl --user -u myagent -f
```

## Структура

```
agent.py           # агентский цикл, схемы инструментов, API-клиент
bot.py             # Aiogram-бот, тумблеры, доставка, резолвинг имён
tools.py           # реализации инструментов (файлы, память, web, голос, напоминания)
phrases.py         # UI-строки
server.py          # сервер управления удалённым ПК (TLS + legacy-мост)
start_remote.sh    # перезапуск сервера удалённого доступа
remote/            # клиенты, шаблоны, инструменты для удалённого ПК
system_prompt.txt  # личность агента (не в git, личное)
*.db               # история, состояния, память, напоминания (не в git)
bin/ffmpeg         # локальная копия ffmpeg (не в git)
```

## Безопасность

- `.env`, базы, бэкапы и `system_prompt.txt` — в gitignore.
- `telegram_send` — только для владельца; деструктивные запросы отклоняются
  для всех без исключений.
- Терминал жёстко привязан к аккаунту владельца.
- Секреты `remote/` (токены, TLS-ключи, клиентские файлы с токенами) — в gitignore.
  Клиенты собираются из `remote/templates/*.tpl` скриптом `remote/gen_clients.py` —
  в шаблонах только плейсхолдеры.
- Канал к ПК: TLS 1.2 с пиннингом сертификата (SHA-256). Plain HTTP оставлен
  только как legacy-мост для первичного обновления старых клиентов.
